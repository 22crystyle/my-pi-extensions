# Описание проекта

Этот файл описывает проект **browser-tool** и границы работ для AI Dev агентов.

AI Dev агент обязан читать этот файл перед любой работой.

---

## Продукт

**browser-tool** — расширение для `pi-coding-agent`, которое предоставляет инструменты для browser automation.

Цели проекта:
- автоматизация сценариев работы в браузере;
- поддержка разных backend-провайдеров browser automation;
- ограничение объёма данных, возвращаемых агенту;
- настройка областей/селекторов, по которым агент получает данные;
- поддержка TUI/UI-конфигурации для управления сценариями и подключениями.

Текущий приоритет:
- автоматизация откликов на `https://hh.ru`;
- работа через `camofox-browser`.

---

## Текущий scope

На текущем этапе проект должен покрывать:
- интеграцию с `camofox-browser`;
- получение snapshot и взаимодействие с элементами страницы;
- ввод текста, включая сопроводительное письмо;
- задание адреса camofox через UI;
- задание кнопок, областей и правил извлечения через UI;
- подготовку архитектуры для дальнейшего подключения других backend-провайдеров (`cdp`, `firecrawl`, `agent-browser` и др.).

---

## Структура проекта

Корень проекта:
- `openapi.json` — OpenAPI-спецификация `camofox-browser`
- `AGENTS.md` — главный файл проекта
- `.pi/agents/` — директория локальных агентных инструкций проекта
- `.pi/memory/actions.md` — журнал выполненных действий агента
- `.pi/memory/decisions.md` — принятые архитектурные и проектные решения
- `.pi/memory/architecture.md` — краткая структура и архитектура проекта

Память проекта:

---

## Правила работы агента

- Перед изменениями читать `AGENTS.md`.
- При появлении устойчивых архитектурных решений обновлять `.pi/memory/decisions.md`.
- При завершении изменений обновлять `.pi/memory/actions.md`.
- При изменении структуры проекта обновлять `.pi/memory/architecture.md`.
- Если решение однажды зафиксировано в `decisions.md`, его нужно соблюдать во всех последующих изменениях, пока оно явно не пересмотрено.

---

## Правила обновления

Если агент обнаруживает новую информацию о структуре проекта, backend/browser-провайдерах, TUI-интерфейсах, контрактах tool API, ограничениях контекста или сценариях автоматизации — он обязан обновить соответствующие файлы в `.pi/memory/`.
